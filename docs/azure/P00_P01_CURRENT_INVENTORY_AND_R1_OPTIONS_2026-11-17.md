## 4. P01 remediation comparison — **not a change request approval**

| Option | Exposure effect / limitations | Registration and cost | Rollback and required tests |
| --- | --- | --- | --- |
| **A. Disable dev ingress (preferred immediate containment candidate)** | Blocks direct inbound HTTP/WebSocket traffic to that app, without changing the shared environment or prod-like app ingress. Does **not** stop background writes or isolate shared storage. | No Entra registration needed. Consumption replicas may scale to zero in the absence of an alternate trigger; shared storage/registry/monitoring charges continue. | Snapshot existing ingress settings **in restricted storage**; after separate authorization use \`az containerapp ingress disable --name "<DEV_APP>" --resource-group "<RESOURCE_GROUP>"\`. Confirm external and intra-environment routes blocked without requests to production. Roll back only to exact previously approved ingress transport/port/visibility/restrictions; do **not** casually reopen public ingress. |
| **B. Restrict ingress / IP allowlist** | Keeps dev reachable from specified networks, subject to Azure environment and route semantics. An internal ACA app endpoint is not necessarily private VNet access. Does not authorize users or isolate storage. | No Entra registration necessary; network/egress and administrative review may have cost. | Save existing rules/transport/target port privately; test approved network, unapproved network, direct revision/label endpoint; restore original rules only with security approval. |
| **C. Entra auth + assigned-users policy** | Can support authenticated dev testing; tenant-only login is **insufficient** for app authorization. Requires end-to-end role/site and WebSocket/download checks. Does not isolate dev data. | Existing app registration cannot be assumed reusable; registration owner, redirect URI, assignment, admin consent, identity secret/expiry and licenses need review. | Enable authenticated-only middleware and required assignment in a separately approved change. Prove signed-out, unassigned, wrong-tenant, revoked users blocked; authorized users pass (including WebSocket); restore only approved previous state, without opening unauthenticated access inadvertently. |
| **D. Stop dev revision/workload** | Separate operational choice, not equivalent to setting \`minReplicas=0\`; HTTP ingress can wake a scale-to-zero app. May stop background writes if all active revisions/trigger paths are verifiably inactive, but breaks testing. | May reduce replica compute consumption, not storage or other resource charges. | Snapshot revision/traffic/scale settings, obtain explicit operational approval, verify no active replicas or other trigger; reactivate exact prior revision settings only in a controlled rollback. |

Microsoft's current ACA documentation describes \`ingress disable\`, IP ingress restrictions, authentication middleware and scale-to-zero semantics. The app-specific values and effective controls must be read again before using any command; the placeholders above intentionally do not disclose or guess them. Do **not** run a signed-out HTTP probe just to check status when the dev app can wake from zero without authorization.
